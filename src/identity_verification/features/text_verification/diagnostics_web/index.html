Upload one two-page PDF per document, or select the front and back images together. The POC extracts printed identity data, validates the machine-readable zone (MRZ), cross-checks both sources within each document, and then compares the older and current identity records.

Final text-verification outcome

What this result does — and does not — mean

The result describes consistency of identity text and MRZ evidence. It is not a claim that the physical card is authentic. Chip/NFC validation, tamper detection and face verification are outside this text POC.

Exact verification workflow used by this POC

There are three distinct checks. They are deliberately kept separate so an OCR error is not confused with a true historical/current identity mismatch.

1

Extract printed fields

The configured lightweight OCR engine reads the visible Emirates ID number, date of birth, English/Arabic names, nationality, sex and expiry date. The engine's own field-level confidence is retained as extraction evidence.

2

Validate each document's MRZ

The system reconstructs the TD1 MRZ and recomputes the document-number, date-of-birth, expiry-date and composite check digits. If the first read does not fully validate, only the MRZ crop is re-read using the fallback path.

3

Cross-check, then compare old vs current

Checksum-protected MRZ values are cross-checked against the printed fields on the same card. After that same-document validation, the canonical older and current records are compared field by field.

MRZ rule: a checksum passing does not by itself mean the front matches the MRZ. First the checksum tells us whether the MRZ read is internally consistent; then the validated MRZ value is compared with the printed value from the same document. Only after that do we compare the older record with the current record.

Same-document MRZ validation

Each card is checked independently before old-versus-current comparison. The four MRZ checks below validate defined character ranges; there is not a separate checksum for every individual character. A failed check triggers another MRZ read or manual review — it is not proof of forgery.

Decision rules currently used

Critical historical/current fields

Emirates ID number and date of birth must match exactly after normalization.

Name evidence

At least one English or Arabic name must be comparable. Uncalibrated fuzzy name variation is routed to review.

MRZ validation

An unresolved MRZ checksum failure after the local fallback path routes the document to review.

Printed ↔ MRZ contradiction

A hard contradiction is raised only when the relevant MRZ value is protected by a passing checksum.

Supporting fields

Nationality and sex are still extracted from the printed card by OCR and compared old-versus-current. The MRZ also exposes nationality and sex, but those same-document MRZ comparisons are supporting evidence because the fields do not have dedicated TD1 check digits.

Current expiry

The current document must contain a valid, non-expired expiry date.

Processing path and latency

The expensive step is OCR inference. Normalization, checksum arithmetic and string/date comparison are negligible by comparison. The MRZ fallback is conditional so clean cards do not pay a second-reader cost.
